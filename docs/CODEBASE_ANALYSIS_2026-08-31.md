## Executive summary

**This is a very healthy codebase — one of the strongest self-audit cultures the analysis has seen — with its residual risk concentrated in three places: fire-and-forget async hygiene, the seams the FK graph cannot reach (the split vector database), and the storage layer's real SQL never executing in CI.**

Every reviewer independently opened with a version of the same sentence: "one of the most {security-hardened, correctness-conscious, performance-conscious, disciplined} codebases I have audited." That is earned, not accidental. The repo's numbered audit lineage (H/M/L/C/W/S findings cited in code comments, with tests keyed to the same IDs), ratcheted quality gates (coverage thresholds set to measured reality, a shrink-only tsconfig debt list, bundle invariants that hard-fail CI), and honest docs (TECHNICAL_DEBT.md items verified real; CODEBASE_AUDIT.md's RESOLVED claims all verified present) mean past findings stay fixed and new code lands against enforced invariants.

**The three confirmed high-severity findings:**

1. **A transient DB blip during the notification crons can crash the whole API process.** Three `void sendPushToUser(...)` calls in `server/emailScheduler.ts` (lines 113, 161, 215) have no `.catch`; `sendPushToUser` awaits a real Drizzle query *before* its `Promise.allSettled` guard, and the process-wide policy (`server/bootstrap/observability.ts:157-162`) answers **any** unhandledRejection with `logger.fatal` + exit(1). One failed `getSubscriptionsForUser` during the 09:00 UTC weekly-summary burst drops every in-flight request. Every other fire-and-forget site in the repo appends `.catch` — only these three don't. *(Correctness, confirmed high.)* **Resolved 2026-09-01 (PR #1893):** all three sites append `.catch`; the sibling `void`s the verifier found were audited and are safe (`recordAiUsage`/`checkAiBudget`'s caller already wrap their bodies in try/catch that can't reject).

2. **Deleting a coaching material orphans its RAG chunks on the split vector DB — and the deleted content keeps feeding coach prompts.** `DELETE /api/v1/coaching-materials/:id` relies on FK cascade, but `document_chunks` lives on `vectorPool` (a separate Postgres in production) with no FKs at all; `deleteChunksByMaterialId` exists with zero production callers, and retrieval filters by `user_id` only. A user who deletes an uploaded PDF keeps getting coached from it indefinitely, and its text stays at rest — a GDPR Art. 17 gap the account-deletion flow explicitly solved for the whole-account case but the per-material path misses. *(Data integrity, confirmed high.)* **Resolved 2026-09-01 (PR #1893):** `coaching.ts`'s delete route now calls `deleteChunksByMaterialId`, and a daily `ragChunkPrune` cron (`server/cron.ts`) sweeps pre-existing and delete-failure orphans.

3. **The ~9,300-line storage layer's real SQL almost never executes in CI.** Storage unit tests wholesale-mock `db` (and in places drizzle-orm itself); the behavioral real-Postgres suite is 6 happy-path tests. `deleteUserAndPrivateCustomFoods` — the GDPR erasure transaction — has **zero executed coverage anywhere** (the route test mocks the method; the cascade test is a static schema assertion). A wrong predicate in that transaction would ship green. The CI infrastructure to fix this (real pgvector Postgres, drizzle-kit push, an integration lane) already exists. *(Testing, confirmed high.)* **Resolved 2026-09-01 (PR #1895, PR #1896):** five storage-layer integration suites now run the real SQL, including `erasure.integration.test.ts` exercising `deleteUserAndPrivateCustomFoods` directly.

One mapper-level high sits alongside these (not skeptic-verified, evidence strong): **the evidenced run-pace ceiling is dead on arrival** — server `getRunPaceRatio` deliberately returns ratios up to 2.2 for athletes with 8+ logged runs (the audit-M4 fix), but `shared/plannedSessionEstimate.ts:230-232` re-clamps every incoming ratio to 1.25, silently squashing the evidence and partially reinstating the M4 defect (duration underestimates feeding fuelling targets and planned UTSS). No test covers a ratio between 1.25 and 2.2 passing through. **Resolved 2026-09-01 (PR #1893):** `normalizeRunPaceRatio` clamps to the exported `MAX_RUN_PACE_RATIO_EVIDENCED` (2.2), with a test covering a ratio in that widened band.

## Subsystem notes

### Server: AI & coaching services — 8/10 (~9k LOC reviewed)
The AI brain: TrainingContext assembly → sanitized prompt renderers shared verbatim across chat/auto-coach/review-notes/plan-adjustment → provider abstraction (Gemini/Anthropic/OpenAI-compatible) with retries, a DB-persisted circuit breaker, kill switch, budget tracking → zod-validated output applied transactionally behind `aiModificationGuard`'s sha256 prescription fingerprints.
**Standout:** a dedicated 859-line prompt-inclusion regression test; injection defense on nearly every user-authored string; fingerprint-based suppression of repeated fatigue-reductions.

## What is exceptional (keep doing this)

- **The audit trail as an institution.** Numbered findings (H/M/L/C/W/S) cited in code comments AND in test names, with characterization tests (`test/audit/criticals.audit.test.ts`) pinning known-wrong behavior until fixed, and analysis docs whose RESOLVED claims verify against the code. Several tests document that they *inverted* a previously wrong expectation. This is why the same bug classes don't recur — and when one does (the featureBuilder unit-drift fix leaving siblings, this document's C2/D2), the lineage makes the remaining sites enumerable.
- **Enforced invariants over convention**: the protectedRouteBuilder compliance test, the guard-order matrix, the cascade sweep with a "guards the guard" count, SQL-shape tests, the OpenAPI snapshot gate, bundle-structure hard-fails, migration double-apply, the shrink-only tsconfig debt list, coverage ratchets set to measured reality.
- **Concurrency taken seriously at the DB**: advisory-lock registries with collision warnings, claim-before-send ledgers, single-use HMAC state claims, SELECT FOR UPDATE, partial-unique-index dedupe, a persisted circuit breaker.
- **The shared/ purity contract**: DB-free, I/O-free calculators with reasonCodes and null-not-zero semantics, imported by both sides so the two can never disagree on a number — with a bundle guard ensuring drizzle never reaches the browser.
- **Privacy engineering**: consent-deferred Sentry with per-processor opt-out, two-phase GDPR erasure ordered around FK set-null, vector-DB purge the cascade can't reach, log redaction as a maintained discipline with one source of truth shared with Sentry scrubbing.
